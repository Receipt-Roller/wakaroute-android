# ワカルート Android

高校受験にむけて学ぶ中学生のための、無料の学習アプリです。
「いまどこにいて、次に何をすればよいか」が分かることを目的にしています。

- 本番サイト: <https://wakaroute.com/>
- Web: [`Receipt-Roller/wakaroute-web`](https://github.com/Receipt-Roller/wakaroute-web)
- iOS: [`Receipt-Roller/wakaroute-ios`](https://github.com/Receipt-Roller/wakaroute-ios)
- 運営: 株式会社レシートローラー / <support@wakaroute.com>

**アカウントは起動時に作ります**（iOS と同じ）。MANABU2 のコンテンツ API は
認証必須で、`GET /courses/{id}` はトークンなしだと 401 です。以前は最初の
書き込み（志望校の登録）まで遅らせていましたが、**先にレッスンを開いた生徒は
「レッスンはまだ読み込んでいません」で行き止まり**になり、しかも画面には
理由も次の一手も出ませんでした。志望校を引き金にする理由は無かったので、
2つのアプリの振る舞いをそろえています。

## 動かす

必要なもの: **JDK 17〜21**、Android SDK（compileSdk 36）。

```bash
./gradlew :app:installDebug
```

`local.properties` に `sdk.dir` が必要です（gitignore 済み）。

### JDK は 25 では動きません

Gradle 8.13 は JDK 25 に対応していません（JDK 25 は Gradle 9.1 以降）。
**Android Studio 2026.1 は JBR 25 を同梱している**ので、既定のまま Gradle を
動かすと何もビルドできません。しかも失敗が
`IllegalArgumentException: 25.0.2` として Kotlin コンパイラの中で出るため、
**Kotlin のバージョンの問題に見えます。違います。**

Android Studio では **Settings → Build → Build Tools → Gradle → Gradle JDK**
を 21 に向けてください。IDE 自体は JBR のままで構いません。

`core` が要求する JDK 17 のツールチェインは、`settings.gradle.kts` の
foojay プラグインが自動で取得します。**ビルドが「そのマシンに何が入っているか」に
依存しないように**するためです。

## 検証

```bash
./gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:compileDebugAndroidTestKotlin :app:assembleRelease
```

Release ビルドまで通してください。**R8 が kotlinx.serialization のシリアライザを落とすと、
Debug では何も起きず、Release だけが全レスポンスで例外になります。**

## 構成

```
core/     Kotlin/JVM — ロジック（エミュレータなしでテストできます）
app/      Android — 画面のみ
```

### なぜ core を分けているか

`core` は Android ライブラリではなく **Kotlin/JVM モジュール**です。
`./gradlew :core:test` が端末もエミュレータもなしで走るようにするためで、
iOS が `WakaRouteKit` を Swift パッケージに分けているのと同じ理由です。

同梱データ（前提関係グラフ、法的文書）も Android の asset ではなく
**JVM リソース**として読んでいます。端末でしか読めないデータは、
検証が CI で走らないデータだからです。実際、前提関係グラフの
巡回・欠けた辺・重複は、実行時ではなく `:core:test` で落ちます。

### 設計

```
View → ViewModel → Repository → API クライアント / キャッシュ
```

読み込み中・成功・0件・失敗・再試行は、null で暗示せず**明示的な状態**として持ちます。
「電波がない」と「サーバーが落ちている」は生徒にとって別の話なので、
`SearchFailure` で区別し、再試行できるものだけに再試行ボタンを出します。

## 設計上の判断とその理由

### 理解度はレベル2までしか出しません

レベル3以上には**項目ごとの**確認テストが必要で、まだ作られていません。
画面には**レベル2までしか出しません**。「未達成」とも「準備中」とも描きません。

MANABU2 にあるスタート診断は領域（path）全体を14問で通すテストです。
合格しても、その中のどの項目が固いかは分からないので、**理解度には使いません**。
**誰も測れないレベルで、生徒が落第したことにはできません。**

同じ理由で、進捗のカウントは「習得」ではなく「基本を解ける以上」を数えます。
いま何も習得にならないため、習得で数えると全部やり終えた生徒にも 0/26 と出ます。

### 「まだ届いていない」と「つまずいた」を分けます

初回起動では26項目中23個が blocked です。まだそこまで行っていないので当然で、
これを「つまずき」と呼ぶと**学習を始めた全生徒の全領域で警告が点灯し続けます**。

**つまずきの証拠はクイズの不合格だけ**です（`MasteryRecord.struggling`）。
iOS はこの系統の間違いを3回踏んでいます。

### 数学以外の4教科に空のグラフを渡しません

辺が無いグラフでは全項目が「学習可能」になり、
画面は4教科について「つまずきはありません」と答えます。
**この地図が絶対に出してはいけない答え**なので、`SubjectMapState.ComingSoon` を返し、
画面はその教科を**表示しません**（「準備中」とも書きません。まだ無いものは見せない）。

同じ理由で、**配信されたグラフでも `requires` が1本も無ければ表示しません。**
MANABU2 にコンテンツが揃うことと、前提の辺が書かれることは別の話です。

### 「学ぶ」と「理解マップ」は別のものです

**学ぶ**は5教科すべての内容を、領域 → 項目 → レッスンの順にたどる入口です。
MANABU2 のパスを**教科ラベルで**分けています（名前は解析しません。iOS の
`SubjectCatalog` と同じ規則）。順番を並べるだけで、「どこへ戻るべきか」は言いません。

**理解マップ**は前提関係の辺がある教科だけのもので、いまは数学だけです。
学ぶの数学の下から開きます。

### 教科はアプリ更新なしで増えます

前提関係の辺は MANABU2 に存在しません（コース・パスに prerequisite の概念が
ありません）。順番と前提は別物で、順番では「一次関数で止まっているのは
文字を用いた式が原因です」と言えないからです。

そのため辺はワカルート側のデータで、`GET /api/prerequisites` から取得します。
取得したグラフは同梱のものと**同じ検証**（重複・行き先のない辺・循環）を通し、
落ちたものは保存しません。取得できなければ、同梱の数学と前回保存したものが
そのまま残ります。

### 引き継ぎは、送れていない記録を置き去りにしません

ログインはこの端末のアカウントを**置きかえます**。キューに残っている記録は、
その瞬間から生徒がもう辿り着けないアカウントのものになります。
危ないのは**ログインがどちらの場合も成功する**ことで、生徒には前の記録が
戻ってきたように見えます。

`AccountHandover` は先に送信を試み、それでも残るなら**件数を添えて拒否**します。
黙って捨てるのも、生徒に選ばせずに止めるのも違うと考えました。

### 削除は「サーバーが先、端末はあと」です

先に端末の資格情報を消すと、通信が失敗したときに**生徒が二度と辿り着けない
アカウントがサーバーに残ります** — 消してほしいと言った人を、消せなくするだけです。
失敗時は何も触らず、「記録はそのまま残っています」と伝えます。

### レッスンの数式は平文に直します

レッスン本文は数式を `<span class="math">\(…\)</span>` で囲んでいます（MathJax の
書き方）。Web は数式レンダラを通しますが、このアプリはネイティブに描くので、
**そのままでは `\(3-5\)` や `\dfrac{1}{2}` が生徒に見えていました。**

本番で数えると数学293レッスン中69、14,536か所。使われているコマンドは
閉じた小さな集合（`\dfrac` `\times` `\div` `\left` など）で、`^` も `\sqrt` も
無いので、数式レイアウトエンジンではなく `MathNotation` で平文に直しています。
テストの問題は `$…$` で書かれていて、`^{2}` や `\leqq` も使います（本番の330問で確認）。
`MathNotation.toReadableText(text, dollarDelimited = true)` で読みます。分数のすぐ後に
項が続くときは `(1/2)x²` と括弧を付けます — `1/2x²` は 1/(2x²) と読めてしまうからです。
**知らないコマンドはあえて残します** — 黙って壊れるより、レビューで気づけるほうが
ましだからです。

### JavaScript を使うレッスンだけ WebView の島にします

「両辺に同じ数を足す・引く」には、押すとさおが傾く天びんがあります。
ネイティブに描くと図は止まったまま、ボタンはただの文字になります。

そこだけ WebView に載せ、**残りはネイティブのまま**にしています（文字サイズ・
TalkBack・オフラインはネイティブでしか成り立ちません）。**これはレッスンの
作者が書いたコードを実行する**ので、サンドボックスが本体です。

- **通信は一切させません。** 全リクエストを空で返し、base URL も null です。
  レッスンがトラッカーを読み込むことも、誰が開いたかを漏らすこともできません
- **アプリへの橋を渡しません。** `addJavascriptInterface` は呼びません。
  高さの通知だけは `document.title` 経由で、参照を渡さない一方向です
- **ファイル・コンテンツ・ストレージへのアクセスなし。画面遷移もさせません**

### WebView を使いません（本文以外）

規約・ポリシー・受験ガイドはすべてアプリに同梱しています。
中学生をブラウザに飛ばすと戻ってこられるか本人任せになり、
圏外では読むことすらできません。
同梱文書は本文パーサを通して描画するので、文字サイズ設定にも TalkBack にも従います。

### アクセス解析とクラッシュ収集を入れていません

プライバシーポリシーに明記済みです。導入は公開文書の変更を伴います。

### バックアップを無効にしています

Phase 2 で `deviceSecret` を保管します。復元された `deviceSecret` は、
2つのインストールが同じ生徒を名乗れるということです。
鍵が生まれる前に切っておくほうが、後から切り忘れるより安全です。

### 端末で分岐しません

`if (isTablet)` は分割画面とフリーフォームで破綻します。
判断は**フォントスケールと幅**で行います（`AdaptiveRow` / `ReadableColumn`）。
アイコンとシェブロンが幅を保つと、最大サイズで日本語が1〜2文字ずつ折り返されるため、
大きい文字では行を縦積みに切り替えます。

### 色だけで意味を運びません

`StatusChip` は記号と言葉を必ず添え、枠線も引きます。
